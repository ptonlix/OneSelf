# 这个人是谁，最近过得怎样

`self/soul` 记录已经得到证据支持的长期特征，以及尚未确认的候选观察。`self/recent` 记录最近仍有效的生活状态。其它目录里的页是证据。上传一份资料，本身不是写入这两页的理由。

没有这两页的读权限时停下来，不要另写总览。回答这个人是谁时，只用 Soul 上面六节。候选观察不能说成已经确认的特征。

两页都用 `edit_page` 修改，必须带当前哈希。不要对这两页调用 `remember`、`forget` 或 `add_timeline_entry`。那些操作会被拒绝，原文不变。Soul 和 Recent 里所有带描述后缀的判断区、候选区和时间线，都是 Agent 维护的普通 Markdown，不是系统的 `## Facts` 或 `## Timeline` 围栏。看到 `Timeline` 或 `Facts` 这几个字，也不要改走那两个操作。不要创建 `self/observations`。不要把密钥或凭据写进来。公开请求使用 `credentials: omit`，不得写入密钥或私有页，也不得把密钥或 private 页写进源码或构建产物。没有人要求公开时保持 `private`。

`self` 是内置目录。服务启动时，若该目录没有被软删除，会用下面的空模板补上缺失的 `self/soul` 和 `self/recent`。`as_of` 是生成当天。已有正文不覆盖，也不迁移旧页。Agent 不要再创建这两页，也不要用不带哈希的写入覆盖空模板。读到空栏目就留空。怎么观察，看 `references/cognition.md`。这里只写结果放哪里。

Soul 是长期内在特征，不是简历。Recent 是仍有效的近期生活，不是上传记录。一次偶然不进入上面六节。

## 六节怎么分

- `01. Values — 价值观与信念`：长期相信什么、拒绝什么。一次抱怨不是价值观。
- `02. Thinking — 思维与认知`：怎样理解问题和形成判断。不是知识清单。
- `03. Operating — 做事与决策`：怎样做决定、怎样推进事情。不是岗位描述。
- `04. Habits — 习惯与行为规律`：反复出现的做法。一次行为不是习惯。
- `05. Motivations — 内在动机`：长期追求什么。愿望还没变成行动，不要写成已经形成的规律。
- `06. Strengths & Frictions — 优势与摩擦`：反复帮助或反复挡住这个人的事。不是一次成败。

「我不喜欢被别人安排」不能自动归类。多份资料都显示他为自主权付出额外成本，才可能进入 Values 或 Operating。只是一次冲突里的情绪，写进 Recent，不要升入六节。没有长期线索时，也不进候选。

## 每次整理

1. 观察：从新资料里找出可能有关的长期规律或近期状态。
2. 对照：读 `self/soul` 的正式画像和候选观察，以及 `self/recent`。
3. 判断：一次偶然不进入上面六节，也不自动进入候选，只保留原始证据。单次事件若有值得以后再验证的长期线索，才可以进入候选。多次出现但还不能确定，留在候选。多份独立资料相互印证，可以作为行为观察写入对应的一节。本人明确确认的内容，可以作为用户自述进入正式画像，但必须保留自述性质，不能因此写成已被行为验证的事实。价值观和信念的明确表达，记成自我认知，不是习惯。反证出现时重新评估，不要静默覆盖。近期信息若仍然有效，写入 `self/recent`。
4. 清理：候选不是收集箱，也不是所有不确定信息的垃圾桶，只保留值得以后再验证的假设。没有长期线索的一次出现、只在某个项目里成立、已经不值得再看的，不要留下。合并说的是同一件事的候选，保留更早的 `first_seen`，把证据并到一起。相反证据写进 `note`；已经推翻的删掉。很久没有新证据，不晋升，也不因为沉默自动删除；下次整理时若已经不值得继续看，再删。本人明确否认的，删掉或在 `note` 写下否认，不得晋升。晋升后从候选区删除，避免同一判断算两次。`valid_until` 已过的近期判断退出当前栏目，不按自然月归档。仍值得记住的变化，改写进 `Timeline — 近期重要变化`，那是变化记录，不是当前状态。

## Soul 模板

```markdown
---
type: soul
title: 灵魂画像
name: ""
visibility: private
tags: []
files: []
---

# Soul — 长期个人认知

这份文件描述一个人的长期内在特征。
它不是简历、个人介绍，也不是 Agent 的行为指令。

只记录经过证据支持的长期判断。
不确定的内容不进入正式画像。

## 01. Values — 价值观与信念

## 02. Thinking — 思维与认知

## 03. Operating — 做事与决策

## 04. Habits — 习惯与行为规律

## 05. Motivations — 内在动机

## 06. Strengths & Frictions — 优势与摩擦

## Timeline — 认知演化

只记录重要认知的建立、修正与失效。

## Observations — 候选观察

记录尚未充分确认的潜在规律。不能当作已经确认的特征。
```

正式判断只写在对应的一节里。不知道就留空，不要填。每条写清判断、来源、范围和证据。来源只使用用户自述、行为观察、Agent 推断。用户自述不能写成已被行为验证的习惯。范围写它在什么事情上成立，不要写成这个人的全部。不要写 confidence、status、evidence_type 或 scope 这种评分字段。

```markdown
- 判断：倾向于自己搭建工具，以换取长期控制。
  来源：行为观察
  范围：技术选择与个人项目
  证据：
  - "[[work/oneself]]"
```

Recent 里的近期状态不会自动晋升。刚开始早起只写 Recent。多次持续出现，才可以成为候选。长期稳定，才进入 Habits。同一句话不要抄进两页。需要两层判断时，各写各的层次，证据可以指向同一页。

候选只用下面这些字段。`source` 与正式判断的来源相同，只能是用户自述、行为观察、Agent 推断。晋升时原样带上，不要在正式画像里改写成另一种性质。

```markdown
- observation_id: thinking-001
  statement: 可能更想自己掌握工具，而不是依赖封闭平台。
  source: 行为观察
  evidence:
  - "[[work/oneself]]"
    first_seen: 2026-11-20
    last_seen: 2026-11-20
    note: 还要看这是不是项目条件，而不是长期偏好。
```

`last_seen` 只在出现新的、独立的支持证据时更新。重新读取旧资料，或再次引用同一件事，不算新观察。

## Recent 模板

```markdown
---
type: recent
title: 近期画像
as_of: 2026-11-20
visibility: private
tags: []
files: []
---

# Recent — 近期生活

记录最近一段时间仍有理解价值的生活状态。
不做流水账。过期的判断退出栏目。
有判断的栏目先写一句提炼，判断块写在该栏下。
没有判断的栏目留空。

## 01. Focus — 近期关注

## 02. Work — 工作与事业

## 03. Mood — 情绪与心理状态

## 04. Health — 身体与健康

## 05. Life — 生活状态

## 06. Relationships — 人际关系

## 07. Goals & Challenges — 目标与困扰

## Timeline — 近期重要变化
```

判断块写在对应栏目下，不要另起 `## Facts — 近期有效判断`。`domain` 只能是 `focus`、`work`、`mood`、`health`、`life`、`relationships`、`goals_challenges`，依次对应上面七栏，并且必须和所在栏目一致。不要自造 `career` 或 `job`。同一页里的 `id` 不重复。日期都写 `YYYY-MM-DD`。

有当前判断的栏目，标题下先写恰好一句提炼，再写该栏的判断块。这句只压缩这些块已经写出的主张，不得另加块里没有的说法。提炼不是判断块，不要给它 `id`、`domain` 或 `valid_until`。该栏判断增加、修改、到期或删除时，同一次修改必须重写或删掉这句。栏内没有当前判断时标题下留空，不要写「暂无足够证据」或其它占位句。

`Timeline — 近期重要变化` 仍在七栏之后，只记变化，不重复提炼，也不把当前判断再抄一遍。

栏目下的判断块不是系统围栏，是普通 Markdown，系统不会解析，也不要补上 `entity` 或 `confidence` 去模仿系统 Facts。系统只把标题恰好是 `## Facts` 或 `## Timeline` 的节当成围栏，而且只接受 `id`、`entity`、`statement`、0 到 1 的 `confidence`、`valid_until`。不要调用 `remember` 去写这两页。健康只记录资料里已经出现的状态，不要诊断，不要把相关写成因果。

下面是写在 Work 栏下的例子，不要抄进空模板。

```markdown
## 02. Work — 工作与事业

正在推进个人上下文。

- id: work-001
  domain: work
  statement: 正在推进个人上下文。见 [[work/oneself]]
  observed_at: 2026-11-20
  valid_until: 2026-12-20
  evidence:
  - "[[work/oneself]]"
```

`as_of` 只在这次确实改了 Recent 时更新，不是每条判断的有效期。`observed_at` 是事情发生或被观察到的日期，不能用上传日期代替。凡是要当作当前状态引用的判断，都必须有 `valid_until`。它是最晚还可以当作现状引用的日期，不是变化发生的那天。定不出自然终点时，写一个复核日期，不要无限期引用。情绪写得短一些。健康按这份资料本身的性质。工作按项目周期。长期目标写到目标变化或再次确认。没有 `valid_until` 的句子不能当成当前状态。到期后退出当前判断：还有回顾价值的改写进时间线，没有价值的直接删除。旧资料不能写成现在的生活。Recent 没有候选区。

两条时间线都用同一行：`日期 | 变化 | 补充`。例如 `- 2026-11-20 | 工作重心变化 | 开始把更多时间投入个人上下文。` 只记重要变化，不记普通日常，也不重复提炼或当前判断。已经结束的状态不再当作现状引用。

# Design

## Context

见 `proposal.md`。`GET /admin/oauth-grants` 现在只返回 `id`、`site_write`、`unrestricted_data`、`sources`、`created_at`、`revoked_at`。授权编号是授权库生成的随机 id，不是密钥，也不是 Agent 名称。刷新到期只存在于进程内适配器：签发时是现在加 30 天，进程重启时 `seed()` 又把已保存的刷新令牌改成现在加 30 天，不读库里的载荷。`refresh_token_payload` 不能交给浏览器。

`openspec/specs/access` 还不存在。本变更替换尚未归档的 `redesign-orbit-ui` 里「列表正好五个字段」和「概览不显示名称、最近使用、过期」这两条要求。`device-unrestricted-data` 增加的 `unrestricted_data` 保留。

## Goals / Non-Goals

**Goals:**

- 所属人批准时留下一个只给自己看的标签，概览用它分辨每一条授权。
- 列表给出和 API Key 同一含义的最近使用时间，以及当前刷新令牌的到期时刻。
- 重启后的可接受期限和列表上的到期是同一个时刻。

**Non-Goals:**

- 不改 30 天滑动期限，不解析 `refresh_token_payload`，不让 Agent 起名或改名。
- 不给已有授权补标签，也不提供事后修改标签的接口。
- 不把授权码流程变成生产入口。该路径只在测试配置存在，标签保持可空。

## Decisions

1. **标签只从 `POST /admin/device` 进入。** 请求体增加 `label`。服务端 trim，空或超过 80 个字符用现有 `invalid`，不批准。不新增错误码。管理端在提交前做同样检查。授权码测试路径插入的授权 `label` 为 `null`。
   备选是让 Agent 在申请设备码时自报名称。这会让 Agent 改写所属人看到的名字，提案明确排除。

2. **最近使用写在 access token 认证成功时。** 与 `#actorFromApiKey` 相同：凭据被接受就更新，不看后续操作是否成功。批准、设备码轮询、换 token 和刷新都不写。作废不清这一列。用应用时钟，不用 `Date.now()`。
   备选是把刷新也算使用。那样一条只续期、从未调用资料接口的授权会显得刚用过，和 API Key 的含义不同。

3. **到期单独存 `refresh_expires_at`，响应字段叫 `expires_at`。** 签发或轮换刷新令牌时，把适配器刚刚算出的 `expiresAt` 写入该列。不从载荷的 `exp` 推导。作废时和哈希、载荷一起清空，因为已经没有当前刷新令牌。响应字段不能含 `token`、`refresh` 或 `hash`：管理端解析器和现有冒烟都按这个规则拒绝密钥材料。
   备选是列表时读取载荷。载荷形状不是本仓库的契约，作废后还会被清空。

4. **重启按该列恢复适配器到期。** 有 `refresh_expires_at` 时，`seed()` 用它，不再写成现在加 30 天。该列为空但哈希还在的旧行保持现在的装载方式，列表的 `expires_at` 为 `null`，下次成功刷新再写入。已轮换的旧哈希仍只为重用检测服务，不显示它们的到期。

5. **概览标题用标签，没有标签才缩短 id。** 活动行显示最近使用、批准时间和刷新到期；空值分别写成「从未」和「尚未换到令牌」。已作废的行保留最近使用和作废时间，不显示到期，也没有作废按钮。作废仍用 id，不改两步确认。

## Risks / Trade-offs

- [旧管理端会拒绝多出来的字段] → 管理端和接口同一进程发布，解析器与服务端一起改。
- [每次 access token 调用都写一次最近使用] → 与 API Key 相同，不另做节流。
- [重启后旧行的到期仍被适配器延长，列表却显示空] → 只发生在升级前已经发出、且升级后还没刷新的行。下次刷新后两边对齐。不从载荷回填。
- [PRD 第 6 节的 `oauth_grants` 一行在归档前不会改] → 实现时改 `docs/ARCHITECTURE.md`。PRD 等归档，避免未归档变更改写它。

## Migration Plan

追加一条迁移，只加三列，均可空，不改已有 SQL。回滚是还原应用版本；新列可以留在库里，旧版本不读它们。不补填标签，不删除已有授权。

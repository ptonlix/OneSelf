# Design

## Context

见 `proposal.md`。作废写 `revoked_at` 并销毁令牌，行仍留在 `oauth_grants` 和列表里。没有删除方法。

## Goals / Non-Goals

**Goals:**

- 所属人可以让一条授权从列表消失。
- 仍有效的授权不会在记录消失后继续可用。

**Non-Goals:**

- 不提供恢复。不让 Agent 删除自己的授权。不改作废的含义。

## Decisions

1. **路径用 `POST /admin/oauth-grants/{id}/delete`。** 与作废一样核对 Origin，只认所属人会话。不新增错误码。
2. **软删除，不执行 DELETE。** 追加可空列 `deleted_at`。引擎里若尚未作废，先走现有作废并清掉令牌，再写入 `deleted_at`。行和内存记录都留着，列表过滤掉它。再次删除返回 `not_found`。重启不把已软删除的授权装回令牌适配器。
3. **两处列表都提供两步删除。** 概览和设备码页共用同一接口。确认文案是「确认删除」，避免和「确认作废」混在一个按钮状态里。

## Risks / Trade-offs

- [删除后界面不能恢复] → 行仍在库里，但没有恢复接口。所属人可以重新走设备码批准。
- [旧刷新令牌重放] → 令牌适配器已清掉。内存里仍留着轮换哈希，重放仍会命中已作废的记录并失败。

# Design

## Context

产品 Skill 由站点发出，安装副本在 Agent 侧。`npx skills update [skills...]` 会按已记录的来源更新指定 Skill。管理端已经能匿名读取发现文档和安装索引。索引里 `oneself.digest` 是这次 archive 的 SHA-256。登录后的首页是星图。升级提示不放在星图上，而在 Skill 菜单和 Skill 页。

## Goals / Non-Goals

**Goals:**

- 已有 Agent 时，摘要未确认或与已确认值不同，就在 Skill 菜单点红点，并在 Skill 页给出可复制命令。
- 确认后记住摘要，不反复点亮红点。
- 还没有 Agent 时不把安装流程说成升级，也不在星图上放升级提示。
- Skill 页始终能复制全新安装和升级两条命令。

**Non-Goals:**

- 不检测 Agent 安装目录里的实际字节。管理端看不到那份副本。
- 不自动运行 `npx`，不改 `config.json`，不新增服务端字段。
- 不把升级提示放回星图。

## Decisions

1. **用安装索引摘要判断是否提示，正文只用于展示和对比。** 索引已经是安装器使用的摘要，而且 `no-store`。管理端只认 `name` 为 `oneself` 的那一条。Skill 页另读当前正文，用来展示，并和上一份已确认正文做行对比。

2. **两条命令都在 Skill 页。** 全新安装用 `npx skills add <origin> -a <agent> -s oneself -y`，origin 来自发现文档。已安装的升级用 `npx skills update oneself`，只更新这一份，不接受 URL。两条都用小的复制图标，不做成大玻璃按钮。「发现 oneself skill 有更新，请升级 skill」和「已更新」只在提示生效时出现。「已更新」保持普通按钮。星图仍只保留原有的安装命令，不放升级提示。

3. **确认值存在浏览器本地，按 origin 分开。** 键包含发现文档给出的 origin，避免本机和线上互相盖掉。点「已更新」才写入已确认摘要和正文。没有 Agent 时静默写入当前摘要，这样随后第一次批准不会立刻点亮红点。静默写入时如果已经读到当前正文，一并记下，供之后对比；没有读到正文就不覆盖已有正文基线。首页这条加载本身不读正文，所以在静默记摘要时补读一次。存储失败或补读失败都不挡住星图。

4. **提示在 Skill 菜单和 Skill 页，升级结果也放在终端。** 红点在 Skill 菜单，命令和对比在 Skill 页。直接打开或刷新 `/admin/skill` 必须落到管理端文档，不能 404。`oneself update` 在重启前读一次安装索引。`docker compose up -d` 不等待应用就绪，连接被拒绝会立刻失败，所以重启后短重试几次，次数和总时间有上限。摘要不同才在结束说明里写出两条命令。仍然读不到、dry-run 或摘要相同都不说 Skill 变了，也不让更新失败。dry-run 在重试读取之前返回。终端里的 origin 取自 `PUBLIC_ORIGIN`，只去掉一个末尾斜杠，以便和站点公布的 origin 一致，不改写其他部分。

## Risks / Trade-offs

- [本机没有旧摘要，已接入的所属人会看到一次红点] → 这正是这次升级要通知的人。确认后不再出现，直到摘要再变。
- [安装来源不是当前站点] → 命令更新的是已安装 `oneself` 的记录来源。不在这条提示里改安装来源。

## Migration Plan

随管理端静态包发布。没有服务端迁移。回滚时去掉红点和 Skill 页提示；浏览器里留下的摘要键无害。
